# 快速插件改动对比测试

## 什么时候用
- 当你想在修改、升级插件代码后，立即验证新的实现是否保持旧有行为，或是否产生差异。
- 当你需要在本地提交前给主人演示改动的影响。

## 怎么做
1. **准备测试场景**：在 `tests/` 目录下创建一个或多个 YAML/JSON 输入文件，包含典型或边缘情况。
2. **运行旧版**：使用 `dsh --plugin=your-plugin --input=path/to/input.yaml --output=old.txt` 记录旧行为。
3. **运行新版**：在同一环境下执行 `dsh --plugin=your-plugin --input=path/to/input.yaml --output=new.txt`。
4. **对比输出**：跑 `diff old.txt new.txt`，或者使用 `dsh --compare old.txt new.txt` 自动生成差异报告。
5. **渲染结果**：如果输出为文本、JSON 或图表，可使用 `dsh --view new.txt` 预览最终表现。
6. **确认**：若差异属于预期改动，则记录并提交；若非预期，回滚或进一步修正。

## 注意什么
- **环境一致**：确保 Python、依赖和插件版本在两个测试阶段保持一致，避免版本差异导致误判。
- **输入完整**：不要只跑一个工单，至少做 3–5 条不同类型的输入，覆盖成功案例、错误输入与边缘情况。
- **安全**：不要在测试中使用真实用户数据或敏感信息，使用匿名或脱敏样本。
- **资源限制**：对大型输出文件使用分块读取，避免一次性折腾过多内存。
- **文档化**：在 `CHANGES.md` 里写明此次改动与测试总结，方便日后追溯。

这样，你就能在本机快速验证每一次插件改动的影响，确保“干货”与“诚意”始终对齐。
